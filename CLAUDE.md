# CineFlow Prep — контекст проекта

## Что это
Однофайловое веб-приложение (index.html) для подготовки кинооператора к съёмкам:
сцены с экспликациями, раскадровка со скетчами, галерея референсов с тегами,
интерактивная доска (whiteboard), схемы света с графическим редактором,
таблица смен (КПП), документы, состав группы, командный чат.

Язык интерфейса: русский. Пользователь — оператор-постановщик, не программист:
объясняй изменения простыми словами, без жаргона.

## Стек
- Один HTML-файл, без сборки: React 18 (UMD production) + Babel Standalone (JSX в браузере)
- Tailwind CDN с кастомной конфигурацией (палитра в `tailwind.config` в `<head>`)
- Firebase (compat SDK 10.8): анонимная авторизация + Firestore для синхронизации в реальном времени
- SheetJS (xlsx) — импорт КПП из Excel
- Gemini API (модель gemini-3.6-flash) — ИИ-функции; ключ вводится пользователем
  в меню «Проект», хранится в localStorage (`cf_gemini_key`)

## Дизайн
Стилистика приложения Claude: тёмный тёплый фон (#1a1918), панели #242322,
кремовый текст #f0eee6, терракотовый акцент #d97757 (замаплен на шкалу `indigo`
в tailwind.config — НЕ переопределяй классы indigo-* по одному, меняй шкалу),
тёплые серые (замаплены на `zinc`). Заголовки — серифный Lora, интерфейс — Inter,
моно — JetBrains Mono. Плоские панели, радиус 12px (rounded-xl), без неоновых свечений.
CSS-переменные — в `:root` в `<style>`.

## Архитектура данных
- Все сущности в состоянии React (AppCore): scenes, storyboard, references,
  stickies, docs, crew, projectFiles, gearTypes, lightGearTypes, lightSchemes, messages
- Синхронизация: Firestore `artifacts/{appId}/public/data/{коллекция}`,
  appId = код комнаты из localStorage `cf_room` (по умолчанию 'cineflow-room-3')
- `syncDoc(coll, id, data)` — запись с debounce 400 мс и обработкой ошибок;
  `deleteNetDoc` — удаление; подписки в useEffect сеют локальные данные в пустую комнату
- Резервная копия всегда пишется в localStorage (quota-safe, try/catch)
- Изображения: base64 (jpeg) прямо в документах Firestore. Референсы сжимаются
  до 1440px (`compressImage`), кадры раскадровки до 600px. Лимит документа
  Firestore — 1 МБ; файлы проекта >900 КБ не синкаются в облако
- Чат: senderId = стабильный `cf_client_id` из localStorage; браузерные
  уведомления через Notification API + счётчик в document.title
- Печать: скрытый `#print-area` рендерит все сцены/технику/раскадровку/группу,
  показывается только в @media print (кнопка «Сформировать PDF» = window.print())

## Известные ограничения / план развития
1. Фото хранятся в Firestore как base64 — комфортный предел ~100–150 фото
   на проект. Следующий шаг: перевести изображения на Firebase Storage
   (в базе только URL, ленивая подгрузка)
2. Уведомления работают только при открытой вкладке. Для пушей на телефон
   при закрытом сайте: FCM + service worker (нужен хостинг) или Telegram-бот,
   дублирующий чат в группу
3. Правила Firestore должны требовать `request.auth != null` (задать в консоли Firebase)
4. Схемы света: drawData — только штрихи (прозрачный PNG), preview — собранная
   картинка с фигурами приборов. При изменении редактора обновляй сборку preview
5. Firebase-ключ в файле — это нормально для Firebase (защита правилами),
   но конфиг привязан к проекту prepflow-37284

## Второе приложение: cinelight.html (CineLight — DMX-пульт)
Отдельный однофайловый DMX-пульт в том же стеке и стиле (React UMD + Babel + Tailwind CDN,
та же палитра). Три страницы: Пульт / План / Патч.
- Библиотеки приборов, три источника (производитель → модель → режим DMX, есть поиск):
  1. `FIXTURE_LIB` — выверенный вручную киносвет (Aputure, Amaran, ARRI, Astera, Godox,
     Nanlite, Litepanels, Quasar + базовые и пиксельные профили). Идёт первым в списке.
  2. `OFL_LIB` — 574 прибора / 2534 режима из Open Fixture Library (лицензия MIT).
     Лежит в `<script type="application/json" id="cl-fixture-lib">` — так Babel её не
     разбирает, читается через JSON.parse. Пересобирается `tools-build-fixture-library.js`.
  3. Импорт файлов GDTF: `unzipFind` распаковывает zip силами браузера
     (DecompressionStream, без библиотек), `parseGdtf` читает description.xml
     и переводит атрибуты GDTF в наши роли.
  Плюс конструктор своего профиля с назначением роли каждому каналу.
- Профиль может иметь `dv`/`dv2` — байты для каналов, которыми мы не управляем.
  Для шторки это значение «открыто»: без него ~187 приборов OFL молча не зажигаются.
- Профиль: `{ch:[роли], px:[роли пикселя], pixels:N, ch2:[роли после пикселей]}`;
  footprint = ch + px*pixels + ch2.
  Роли включают 16-битные пары (dim/dimF, hue/hueF, pan/panF, tilt/tiltF) и sat —
  это покрывает режимы CCT/HSI у киношных приборов.
- Программер с поворотными энкодерами (стиль MagicQ: круговое вращение пальцем, режим «Точно»),
  цветовой круг, слайдеры CCT (Кельвины) и тона G/M, RGB/W/A, свотчи.
- Цвет цифрами: CIE 1931 x/y (`xy2rgb`/`rgb2xy`, точка вне охвата sRGB подтягивается
  к ближайшей достижимой), Кельвины, RGB 0–255, оттенок/насыщенность.
- План площадки (`LayoutView`): приборы перетаскиваются пальцем, у пиксельных задаётся
  поворот и длина. Координаты x/y/rot/len лежат в самом приборе. На «Плане» доступны
  та же панель управления, что и на «Пульте» (`controlPanel` — общая переменная), группы
  и инспектор выбранного прибора (`PlanInspector`: имя, адрес, поворот, длина).
- Тяжёлые блоки вкладки «Цвет» (каналы RGB/W/A, цвет цифрами, готовые цвета) убраны
  в `Section` — сворачиваются, состояние живёт в localStorage `cl_sec_*`, в заголовке
  свёрнутого раздела показано текущее значение.
- Движок эффектов (пиксель-мэппинг в духе DyLOS): 8 типов (радуга, волна, бегущий, пульс,
  мерцание, огонь, градиент, строб) × параметры сила/скорость/размер/направление ×
  режим (цвет / яркость / оба) × привязка к выбранным приборам. Для каждого пикселя берётся
  его точка на плане (`pixelPos`), проецируется на ось эффекта, `fxSample` возвращает цвет
  и яркость. Эффекты пишутся в сцену и после записи гасятся, чтобы не наложиться дважды.
- 10 слотов сцен со снапшотами, Grand Master, Blackout. У сцены три времени фейда:
  `fade` (яркость и строб), `fadeC` (цвет), `fadeP` (движение) — `fadeGroupOf(p)` решает,
  какое применить; если `fadeC`/`fadeP` не заданы, берётся `fade`. В такте у сцены три
  бегунка `lvI`/`lvC`/`lvP`, ползущих к общему `target`.
- Списки (`cuelists`): шаги ссылаются на слоты сцен (`{slot, hold}`), своих значений света
  не хранят. Тап по списку = следующий шаг, `hold` в секундах включает автопереход
  (`stepCuelists` в такте). Время перехода берётся из фейдов самой сцены.
- Группы (сохранённый набор приборов) и палитры цвета/позиции. Палитра — живая ссылка:
  сцена хранит `palC`/`palP`, а в такте движка значение берётся из палитры на сегодня,
  поэтому правка палитры тянет за собой все сцены, где она стоит. Ручная правка цвета
  снимает ссылку (`COLOR_KEYS`/`POS_KEYS` в `applyToSelection`). Сохранение палитры сразу
  ставит её на выбранные приборы — иначе записанная следом сцена запекла бы цвет.
- Слепой режим: такт собирает `buildBase()` (сцены) один раз, `addLive()` добавляет
  программер и живые эффекты. `outRef` — что на экране, `dmxRef` — что в кабель;
  в слепом режиме они расходятся. Подсветка «Найти» гасит всё, кроме выбранных.
- Отмена: `pushUndo(label)` кладёт снимок всего проекта (до 40 шагов) перед изменением.
- Работа вдвоём (оператор + пультовик) через тот же мост, без облака: мост пересылает
  текстовые кадры WebSocket всем остальным пультам (`relay`, `peers`), бинарные остаются DMX.
  Пульт шлёт `live` (мастер, блэкаут, цели сцен, программер, эффекты) каждые 100 мс после
  правки и раз в секунду как сигнал присутствия, `project` — с задержкой 800 мс при изменении.
  Приоритет без «главного»: `mark()` ставит метку времени на локальное касание, входящее
  состояние применяется только если `!iOwn()` (прошло >1.8 с с последнего касания).
  `applyingRef` не даёт зациклиться. Выбор приборов НЕ синхронизируется — он у каждого свой.
  Свет в кабель отдаёт один пульт: `settings.dmxOut`; при конфликте уступает тот, у кого
  `CLIENT_ID` больше (localStorage `cl_client`).

### Принцип интерфейса (главное отличие от Onyx/MagicQ)
Задача — та же мощность без их перегруженности. Правила, которые нельзя нарушать:
1. Никакого трекинга: сцена всегда хранит полную картинку. Что видно, то и записано.
2. Одно место для ручных правок (программер), всегда видно по точке на плитке прибора
   и кнопке «Очистить».
3. Всё сохранённое — карточка (`Chip`): тап применяет, долгое нажатие открывает меню.
   Одинаково для групп, палитр и сцен.
4. Три страницы и не больше: Пульт (свет), План (геометрия), Патч (железо).
5. Никакого модального синтаксиса с клавиатурой.
Выходы DMX (частота настраивается: 30/40/44 кадра/с, по умолчанию 40 —
по Wi-Fi часть пакетов теряется, чаще шлём — незаметнее потери; выше 44 бессмысленно,
столько физически проходит по DMX512. Реальная частота считается в `fpsRef` и видна
в настройках):
1. Web Serial → интерфейсы с протоколом Enttec DMX USB Pro (Chrome/Edge на Windows/Mac);
   юниверс для USB выбирается в настройках.
2. Art-Net или sACN (E1.31) через мост — для iPad (там USB недоступен) и любых платформ.
   Пульт сам собирает готовые пакеты (`artDmxPacket` / `sacnPacket`) и шлёт их по WebSocket
   на `cinelight-bridge.js` (Node.js без зависимостей, порт 9070). Мост опознаёт протокол
   по первым байтам пакета (`routePacket`) и рассылает: Art-Net → UDP 6454 broadcast,
   sACN → UDP 5568 в мультикаст 239.255.(hi).(lo) по номеру юниверса; если в argv задан IP,
   всё идёт на него. CID для sACN хранится в localStorage `cl_cid`, номера пакетов ведутся
   по юниверсам. Мост также раздаёт cinelight.html по http://ip:9070 — это решает блокировку
   ws:// с https-страниц: на iPad пульт открывают с адреса моста. Шлются все юниверсы с приборами.
   ВАЖНО: сам cinelight.html тянет React/Babel/Tailwind из CDN, а на площадке компьютер сидит
   на точке доступа ноды — без интернета. Поэтому мост при первом запуске (там, где интернет
   есть) скачивает их в `cinelight-vendor/` и при выдаче страницы подменяет ссылки на
   `/vendor/...` (`localizeHtml`), заодно выкидывая ссылку на Google Fonts. Если папки нет,
   страница отдаётся как есть и требует интернет — мост об этом предупреждает при старте.
   Art-Net идёт не в 255.255.255.255, а в broadcast каждой сети компьютера (`broadcastAddrs`,
   пересчёт раз в 5 с) — иначе при двух интерфейсах (Wi-Fi + кабель) нода в «другой» сети
   ничего не получает. `cinelight-bridge.bat` — запуск на Windows; файл ОБЯЗАН быть в CRLF
   и CP866 (cmd.exe не выполняет bat с UNIX-переводами строк), это закреплено в `.gitattributes`
   правилом `*.bat -text`. Правишь bat — пиши байты через Python, а не обычным редактором.
Без железа — демо-режим (плитки приборов светятся).
Хранение: localStorage `cl_project_v1` + экспорт/импорт JSON. Firebase не используется.
На iPad ставится на домашний экран («Поделиться» → «На экран "Домой"»): мета-теги
`apple-mobile-web-app-capable` дают полноэкранный режим, иконка и манифест вшиты
data-URI (файл остаётся одним). Wake Lock не даёт экрану гаснуть на площадке.
Нативное приложение (Capacitor + UDP-плагин) дало бы только одно — Art-Net прямо
с iPad без моста; всё остальное уже есть. Требует Mac с Xcode и Apple Developer
($99/год), поэтому отложено в пользу моста на Raspberry Pi.
Деплой так же: переименовать в index.html → Netlify Drop (отдельная площадка от CineFlow Prep).

## Как деплоить
Netlify Drop: переименовать в index.html, перетащить на app.netlify.com/drop.
Обновление — перетащить новый файл в Deploys той же площадки.

## Правила работы с кодом
- Файл большой (~1700 строк) — правь точечно, не переписывай целиком
- Проверяй парность скобок/тегов после правок; Babel в браузере молча падает
  на синтаксических ошибках (белый экран)
- Не добавляй сборщики/npm — приложение должно оставаться одним файлом,
  который можно перетащить на Netlify Drop
