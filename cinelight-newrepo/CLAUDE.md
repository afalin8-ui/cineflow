# CineLight — контекст проекта

## Что это
Однофайловый DMX-пульт (`cinelight.html`) для съёмочной площадки.
Три страницы: Пульт / План / Патч. Язык интерфейса русский.
Пользователь — оператор-постановщик, не программист: объясняй изменения
простыми словами, без жаргона.

## Стек
- Один HTML-файл, без сборки: React 18 (UMD production) + Babel Standalone
  (JSX прямо в браузере) + Tailwind CDN с кастомной палитрой в `<head>`.
- Мост `cinelight-bridge.js` — Node.js без единой зависимости.
- Firebase не используется. Проект живёт в localStorage `cl_project_v1`
  плюс экспорт/импорт JSON.

## Дизайн
Стилистика приложения Claude: тёмный тёплый фон (#1a1918), панели #242322,
кремовый текст #f0eee6, терракотовый акцент #d97757 (замаплен на шкалу `indigo`
в tailwind.config — НЕ переопределяй классы indigo-* по одному, меняй шкалу),
тёплые серые (замаплены на `zinc`). Заголовки — серифный Lora, интерфейс — Inter,
моно — JetBrains Mono. Плоские панели, радиус 12px (rounded-xl), без свечений.

## Принцип интерфейса (главное отличие от Onyx/MagicQ)
Задача — та же мощность без их перегруженности. Правила, которые нельзя нарушать:
1. Никакого трекинга: сцена всегда хранит полную картинку. Что видно, то и записано.
2. Одно место для ручных правок (программер), всегда видно по точке на плитке прибора
   и кнопке «Очистить».
3. Всё сохранённое — карточка (`Chip`): тап применяет, долгое нажатие открывает меню.
   Одинаково для групп, палитр и сцен.
4. Три страницы и не больше: Пульт (свет), План (геометрия), Патч (железо).
5. Никакого модального синтаксиса с клавиатурой.

## Библиотеки приборов
Три источника (производитель → модель → режим DMX, есть поиск):
1. `FIXTURE_LIB` — выверенный вручную киносвет (Aputure, Amaran, ARRI, Astera,
   Godox, Nanlite, Litepanels, Quasar + базовые и пиксельные профили).
   Идёт первым в списке.
2. `OFL_LIB` — 574 прибора / 2534 режима из Open Fixture Library (лицензия MIT).
   Лежит в `<script type="application/json" id="cl-fixture-lib">` — так Babel её
   не разбирает, читается через JSON.parse. Пересобирается
   `tools-build-fixture-library.js` (порядок действий — в шапке файла).
3. Импорт файлов GDTF: `unzipFind` распаковывает zip силами браузера
   (DecompressionStream, без библиотек), `parseGdtf` читает description.xml
   и переводит атрибуты GDTF в наши роли.
Плюс конструктор своего профиля с назначением роли каждому каналу.

Профиль: `{ch:[роли], px:[роли пикселя], pixels:N, ch2:[роли после пикселей]}`;
footprint = ch + px*pixels + ch2. Роли включают 16-битные пары
(dim/dimF, hue/hueF, pan/panF, tilt/tiltF) и sat — это покрывает режимы
CCT/HSI у киношных приборов.

Профиль может иметь `dv`/`dv2` — байты для каналов, которыми мы не управляем.
Для шторки это значение «открыто»: без него ~187 приборов OFL молча не зажигаются.

## Управление
- Программер с поворотными энкодерами (стиль MagicQ: круговое вращение пальцем,
  режим «Точно»), цветовой круг, слайдеры CCT (Кельвины) и тона G/M, RGB/W/A, свотчи.
- Цвет цифрами: CIE 1931 x/y (`xy2rgb`/`rgb2xy`, точка вне охвата sRGB подтягивается
  к ближайшей достижимой), Кельвины, RGB 0–255, оттенок/насыщенность.
- План площадки (`LayoutView`): приборы перетаскиваются пальцем, у пиксельных задаётся
  поворот и длина. Координаты x/y/rot/len лежат в самом приборе. На «Плане» доступны
  та же панель управления, что и на «Пульте» (`controlPanel` — общая переменная),
  группы и инспектор выбранного прибора (`PlanInspector`: имя, адрес, поворот, длина).
- Тяжёлые блоки вкладки «Цвет» (каналы RGB/W/A, цвет цифрами, готовые цвета) убраны
  в `Section` — сворачиваются, состояние живёт в localStorage `cl_sec_*`, в заголовке
  свёрнутого раздела показано текущее значение.

## Эффекты, сцены, списки
- Движок эффектов (пиксель-мэппинг в духе DyLOS): 8 типов (радуга, волна, бегущий,
  пульс, мерцание, огонь, градиент, строб) × параметры сила/скорость/размер/направление ×
  режим (цвет / яркость / оба) × привязка к выбранным приборам. Для каждого пикселя
  берётся его точка на плане (`pixelPos`), проецируется на ось эффекта, `fxSample`
  возвращает цвет и яркость. Эффекты пишутся в сцену и после записи гасятся,
  чтобы не наложиться дважды.
- 10 слотов сцен со снапшотами, Grand Master, Blackout. У сцены три времени фейда:
  `fade` (яркость и строб), `fadeC` (цвет), `fadeP` (движение) — `fadeGroupOf(p)` решает,
  какое применить; если `fadeC`/`fadeP` не заданы, берётся `fade`. В такте у сцены
  три бегунка `lvI`/`lvC`/`lvP`, ползущих к общему `target`.
- Списки (`cuelists`): шаги ссылаются на слоты сцен (`{slot, hold}`), своих значений
  света не хранят. Тап по списку = следующий шаг, `hold` в секундах включает
  автопереход (`stepCuelists` в такте). Время перехода берётся из фейдов самой сцены.
- Группы (сохранённый набор приборов) и палитры цвета/позиции. Палитра — живая ссылка:
  сцена хранит `palC`/`palP`, а в такте движка значение берётся из палитры на сегодня,
  поэтому правка палитры тянет за собой все сцены, где она стоит. Ручная правка цвета
  снимает ссылку (`COLOR_KEYS`/`POS_KEYS` в `applyToSelection`). Сохранение палитры сразу
  ставит её на выбранные приборы — иначе записанная следом сцена запекла бы цвет.
- Слепой режим: такт собирает `buildBase()` (сцены) один раз, `addLive()` добавляет
  программер и живые эффекты. `outRef` — что на экране, `dmxRef` — что в кабель;
  в слепом режиме они расходятся. Подсветка «Найти» гасит всё, кроме выбранных.
- Отмена: `pushUndo(label)` кладёт снимок всего проекта (до 40 шагов) перед изменением.

## Работа вдвоём (оператор + пультовик)
Через тот же мост, без облака: мост пересылает текстовые кадры WebSocket всем
остальным пультам (`relay`, `peers`), бинарные остаются DMX.
Пульт шлёт `live` (мастер, блэкаут, цели сцен, программер, эффекты) каждые 100 мс после
правки и раз в секунду как сигнал присутствия, `project` — с задержкой 800 мс при изменении.
Приоритет без «главного»: `mark()` ставит метку времени на локальное касание, входящее
состояние применяется только если `!iOwn()` (прошло >1.8 с с последнего касания).
`applyingRef` не даёт зациклиться. Выбор приборов НЕ синхронизируется — он у каждого свой.
Свет в кабель отдаёт один пульт: `settings.dmxOut`; при конфликте уступает тот,
у кого `CLIENT_ID` больше (localStorage `cl_client`).

## Выходы DMX
Частота настраивается: 30/40/44 кадра/с, по умолчанию 40 — по Wi-Fi часть пакетов
теряется, чаще шлём — незаметнее потери; выше 44 бессмысленно, столько физически
проходит по DMX512. Реальная частота считается в `fpsRef` и видна в настройках.

1. **Web Serial** → интерфейсы с протоколом Enttec DMX USB Pro (Chrome/Edge
   на Windows/Mac); юниверс для USB выбирается в настройках.
2. **Art-Net или sACN (E1.31) через мост** — для iPad в браузере и любых платформ.
   Пульт сам собирает готовые пакеты (`artDmxPacket` / `sacnPacket`) и шлёт их
   по WebSocket на `cinelight-bridge.js` (порт 9070). Мост опознаёт протокол
   по первым байтам пакета (`routePacket`) и рассылает: Art-Net → UDP 6454 broadcast,
   sACN → UDP 5568 в мультикаст 239.255.(hi).(lo) по номеру юниверса; если в argv
   задан IP, всё идёт на него. CID для sACN хранится в localStorage `cl_cid`,
   номера пакетов ведутся по юниверсам. Шлются все юниверсы с приборами.
3. **Прямо с iPad** — в собранном приложении (`app/`), см. ниже.

Без железа — демо-режим (плитки приборов светятся).

### Что важно знать про мост
- Мост раздаёт `cinelight.html` по http://ip:9070 — это решает блокировку ws://
  с https-страниц: на iPad пульт открывают с адреса моста.
- Сам `cinelight.html` тянет React/Babel/Tailwind из CDN, а на площадке компьютер
  сидит на точке доступа ноды — без интернета. Поэтому мост при первом запуске
  (там, где интернет есть) скачивает их в `cinelight-vendor/` и при выдаче страницы
  подменяет ссылки на `/vendor/...` (`localizeHtml`), заодно выкидывая ссылку
  на Google Fonts. Если папки нет, страница отдаётся как есть и требует интернет —
  мост об этом предупреждает при старте.
- Art-Net идёт не в 255.255.255.255, а в broadcast каждой сети компьютера
  (`broadcastAddrs`, пересчёт раз в 5 с) — иначе при двух интерфейсах (Wi-Fi + кабель)
  нода в «другой» сети ничего не получает.
- `cinelight-bridge.bat` — запуск на Windows; файл ОБЯЗАН быть в CRLF и CP866
  (cmd.exe не выполняет bat с UNIX-переводами строк), это закреплено в `.gitattributes`
  правилом `*.bat -text`. Правишь bat — пиши байты через Python, а не обычным редактором.

## Приложение для iPad (`app/`)
Capacitor 7 + плагин `capacitor-udp-socket`. Смысл ровно один: внутри приложения
доступен настоящий UDP-сокет, поэтому iPad шлёт Art-Net прямо в ноду — без компьютера
и без моста. Всё остальное (пульт, библиотеки, логика) — тот же самый `cinelight.html`.

- `prepare-www.js` собирает `www/`: кладёт пульт и его библиотеки внутрь приложения
  (переиспользует `cinelight-vendor/`, если она уже скачана), переписывает ссылки
  на `vendor/...`, убирает шрифты. Интернет приложению не нужен вообще.
- В самом пульте прямой выход включается проверкой `window.Capacitor.isNativePlatform()`
  и наличия плагина `UdpSocket`; в браузере ветка мертва и ничего не меняет.
  `openNative` / `sendNative` / `closeNative`, пакет уходит base64 (`bytesToBase64`),
  есть защита `busy` от накопления промисов.
- Сборка идёт на серверах GitHub (`.github/workflows/ios.yml`, macos-latest),
  сейчас без подписи — это бесплатная проверка компиляции. Для установки на iPad
  нужен аккаунт Apple Developer и четыре секрета, см. `app/README.md`.
- На iPad в браузере пульт по-прежнему ставится на домашний экран: мета-теги
  `apple-mobile-web-app-capable` дают полноэкранный режим, иконка и манифест вшиты
  data-URI. Wake Lock не даёт экрану гаснуть на площадке.

## Правила работы с кодом
- Файл большой — правь точечно, не переписывай целиком.
- Проверяй парность скобок/тегов после правок; Babel в браузере молча падает
  на синтаксических ошибках (белый экран).
- Не добавляй сборщики/npm в сам пульт — он должен оставаться одним файлом,
  который можно открыть с флешки или перетащить на Netlify Drop.
- npm живёт только внутри `app/` и только ради сборки приложения.

## Что осознанно не сделано
- RDM — нужен реальный интерфейс в цепи, проверить нечем.
- Таймкод, видео-пиксельмэппинг, 3D-визуализатор — это вес театра и концертов,
  для площадки не нужен.
- Подписанная сборка iOS — ждёт аккаунта Apple Developer ($99/год).
