# Капелла в Godot — заметки среза «Бой на орбите»

Отдельный проект в папке `godot/` (Godot 4.7.2). Сайт CineFlow и игра на
three.js (`game/`) этим проектом НЕ трогаются; Pages по-прежнему отдаёт
сайт из `master`. Пользователь не программист: всё, что он увидит
(тексты в игре, текст выпуска), — по-русски, коротко и просто.

Что строим и почему — `spec/00-architecture.md`; по шагам — `spec/plan.md`
(пакеты G0…G10, там же отметки, что сделано); поведение боя — доктрина
`spec/09-doctrine.md`; правила и ловушки нынешнего боя — части 01–08.
Здесь — то, что нужно помнить, работая с кодом (список 10.3 архитектуры
плюс найденное по ходу пакетов).

## 1. Слои и двери
- `sim/` — модель боя: чистый GDScript (`RefCounted`), ни одного узла.
  `view/` (3D, интерполяция), `ui/` (Control), `input/`, `audio/` модель
  только ЧИТАЮТ; меняют бой одной дверью — командой `battle.queue(cmd)`.
- **В `sim/` нет** `Node` и прочих узлов, `get_tree`, `Time.`, `Engine.`,
  `Input.`, `OS.`, `DisplayServer.`, `randf()`/`randi()` без генератора боя,
  сигналов и `await`. Проверяет `tests/test_sim_purity.gd` грепом по тексту
  без комментариев и строк (пояснение «Node» в комментарии — не нарушение).
  Откат встроен в тест: грязные строки обязаны краснеть.
- Между модулями — `preload`-константы, а не `class_name`: без импорта
  `class_name` не находится. `const Defs := preload("res://sim/defs.gd")`.
- Папки `input/` и `audio/` появятся с первым файлом (G1, G7): пустые
  папки git не хранит.

## 2. Порядок шага (с G1)
Порядок части 03 (2.1) и 05 (2.2) плюс снимок для ИИ — архитектура, 2.4.
Урон — сразу, а не в конце шага. Расталкивание — по снимку начала шага,
поэтому эталоны наложений из JS перемеряются.

## 3. Объекты + упакованный снимок для пар
Замер: расталкивание объектами каждый с каждым 828 мкс, упакованными
массивами пар 82 мкс. Парные расчёты на объекты не возвращать.

## 4. Оружие по ролям
`main` `sec` `light` `missile` `pd` — у `ShipDef` поля по ролям, а не
`guns[0]`. Загрузчик сводит одинаковые орудия одной роли в одно с `mounts`,
РАЗНЫЕ — громкий отказ («свести в одно нельзя»), а не молча первое.
`main_reach()` — одна функция для выстрела, цели, подхода, отхода, строки
«чем занят» и М1 (с G2). Ловушки 09, 9.5 — переносить дословно.

## 5. Задел на узлы
Свойства корабля — функциями (`thrust()`, `turn()`, `armor_toward(dir)`…),
урон — `damage(…, from_dir)`, тормозной путь — от той же `thrust()`, что
разгон. Узлы кораблей — в данных: `doctrine.json → nodes` (у каждого
`model` — имя узла в сцене: `turret_i`, `aux_i`, `engine_*`, `pd_*`,
`emitter`, `bay`, `hull`; у ракетного пакета «Синхо» — `launcher_0`,
у лёгкого орудия — `muzzle_0`). Выгрузка моделей (G0b) обязана давать
ровно эти имена или править данные.

## 6. Повторяемость (с G1)
Бой = зерно + журнал команд; два генератора (`rng` боя, `fx_rng` картинки);
у записи — заголовок: сборка, отпечаток данных (`defs.fingerprint`), зерно.

## 7. `battle.dispose()` после каждого боя
`RefCounted` не собирает кольца ссылок.

## 8. Стенд (с G5)
Процессами по 25 боёв, `--swap`, `--set путь=число`, `--overrides=файл`,
флажки отката 09, 8.4. Сторону мерить сотней боёв, а не дюжиной.

## 9. Тесты
- Три яруса: `sim` (модель, данные), `ui` (ввод без окна), `render`
  (картинка под xvfb, с G0b). Файл теста — `tests/test_<ярус>_*.gd`,
  `extends "res://tests/case.gd"`, функции `test_*` (могут `await`),
  проверки `ok` / `eq` / `near`. Свой прогонщик `tests/run.gd` печатает
  последней строкой `RESULT checks=N fails=M`.
- **Всё — одной обёрткой** `godot/tools/run_tests.sh` (здесь и в CI):
  импорт → `--check-only` по ВСЕМ скриптам → ярусы под `timeout` →
  строка `RESULT` обязательна → любой `SCRIPT ERROR` — провал → ни одной
  проверки — провал → `-- --selftest` главной сцены → `export_data.mjs
  --check`, `doctrine.mjs --check` и `--selftest` → `.gd.uid` всех
  скриптов в git. Каждое правило обёртки проверено откатом (сломанный
  разбор, ошибка во время теста, зависание, ноль проверок — все четыре
  дают провал). Godot — из `$GODOT`, журналы — в `$LOGS`.
- **Каждая новая проверка — с откатом**: на копии без правки обязана
  краснеть. Откаты G0a: float32 в таблице урона, int без проверки целого,
  `JSON.parse_string` вместо `JSON.new().parse()`, номер строки без +1,
  тихий пропуск недостающего поля, `guns[0]`, торпеда без доктрины, повтор
  F3 без `echo` — все краснеют. Часть откатов встроена в сами тесты
  (испорченная копия в памяти), так их не забыть.
- **Ошибка в базе тестов не останавливает прогонщик**: сломался
  `tests/case.gd` — прогонщик всё равно идёт, валятся вызовы, и строка
  RESULT может выйти с мусором. Поэтому RESULT без `SCRIPT ERROR` — не
  повод верить: смотреть и то, и другое (обёртка так и делает).
- Помощники `tests/hooks.gd`: `click`, `move`, `hovered_at` (аналог
  elementFromPoint), `key(физическая, раскладочная, echo)`, `frames`,
  `set_window_size`. **Размер окна — после первого кадра**: заданный
  в `_initialize` после первого кадра откатывается к 64×64 (перепроверено:
  100×100 → 64×64); `--resolution` не помогает.
- В выгруженной сборке `-s` нет: режимы — аргументами главной сцены после
  `--` (`capella.x86_64 --headless -- --selftest`). Сборка без папки
  `tests/`, `tools/`, `spec/` (exclude_filter).
- Процессы — по PID, никакого `pkill -f`.

## 10. Интерфейс (с G6–G7)
`mouse_filter`: раскладочным `IGNORE` (у `Control`/`Panel` по умолчанию
`STOP`), кнопки HUD `FOCUS_NONE`, клавиши — по `physical_keycode`, повтор
(`echo`) — не нажатие, жест с поля — в `_input`, кнопки не пересоздавать
(C30), свои окна и подсказка. Числа в текст — форматом, не `str()`.

## 11. Отрисовка
Forward+ (Vulkan), откаты на D3D12 и OpenGL включены, MSAA 4× явно.
В Compatibility нет `emit_particle`; `unshaded` StandardMaterial не
светится; в шейдере неба нельзя `return`; дальняя плоскость 20 000
(`doctrine camera.far`), проверка ореола откатом «4000» — в G0b;
постоянное зерно частиц в проверках.

## 12. Данные
- `data/space_data.json` — только выгрузка (`tools/export_data.mjs`),
  руками не править. `data/doctrine.json` — руками.
- **Запись доктрины** — объект с `why` (почему, одна строка) и `sec`
  (раздел 09, проверяется, что он есть), значение — ровно одно из `v`
  (число, таблица или список), `ref` (то же число, что у другой записи:
  `belt.back_on_k` → `main.dead_k`), `rule` (правило словами). `row` —
  ключ строки приложения 09, если имя записи другое; `was` — прежнее
  число. Число вне записи — беда.
- **Добавить число**: запись в `doctrine.json` + поле в `Doctrine`
  (`sim/defs.gd`, путь с `_` вместо точек: `main.dead_k` → `main_dead_k`).
  Запись без поля и поле без записи — отказ загрузки. Особые записи
  (`sec.mounts`, `space_dmg.sec`, `ecm.main_slow`, `clan`, `nodes`)
  раскладываются по своим местам (`DOCTRINE_SPECIAL`).
- `node godot/tools/doctrine.mjs --check`: why и разделы, ссылки на
  кланы/id/классы/ключи выгрузки, порядок порогов 0,4 < 0,45 < 0,5,
  узлы против оружия, все строки приложения 09 закрыты, таблица батареи
  по формуле data.js совпадает с 09, 1.3 — и печатается. `--selftest` —
  11 испорченных копий, каждая обязана краснеть.
- `sim/defs.gd`: поле класса ← ключ JSON в snake_case (`maxSpeed` →
  `max_speed`; `range` → `rng`, `role` корабля → `role_text`). Отказ —
  списком бед в `errors` с путём (`ships.troyden[0]: нет поля «hp»`)
  и строкой у битого JSON; `ok = false`, бой не начинается, `main.gd`
  показывает беды на экране и в stderr.
- **Ловушки чисел** (проверены): все числа JSON — `float` (даже `3`
  и элементы массивов), `int()` — только в загрузчике и только для целого
  (2,5 там, где ждут целое, — отказ); `str(3.0)` = «3.0».
  **`JSON.get_error_line()` считает строки С НУЛЯ** — человеку +1.
  **Разбор JSON в Godot прощает лишнюю запятую в конце**, Node — нет:
  `doctrine.mjs --check` поймает то, что пропустит загрузчик.
  `JSON.parse_string` на битом — молча `null` (тест держит это как
  канарейку). Таблица урона — `PackedFloat64Array`: во float32 0,45 —
  это 0,449999988, и сверка 1e-9 краснеет (проверено откатом).
- Формата `%g` (и `%.12g`) в GDScript нет — ошибка «unsupported format
  character»; дробное — `%.9f` или `String.num()`.
- **Строгая типизация** (`untyped_declaration`, `unsafe_*` — ошибки):
  `int(значение_словаря)`, `bool(…)`, `float(…)` и `x as Dictionary`
  от Variant — ошибки разбора. Работает присваивание типизированной
  переменной: `var n: float = d["n"]`. В тестах для этого помощники
  `dict()`, `arr()`, `num()`, `whole()`, `flag()`, `strs()`, `obj()`
  в `tests/case.gd`. Глушить предупреждения не пришлось нигде.
- Формула клана для батареи: `dmg = roundf(база × gunMod)`,
  `cd = snappedf(база × cdMod, 0,01)` (`Defs.clan_dmg`, `clan_cd`).
  На базе нынешних орудий и ПВО она даёт ровно числа выгрузки — 84 из 84
  (тест), а «toFixed по определению» через сравнение половин ошибается
  на ПВО фрегата Девиана (14,45): snappedf тут вернее.
- Правки без правки файла: `--set путь=число` (повторяемый), `--set=путь=число`,
  `--overrides=файл.json` (`{"путь": число}`), поздний побеждает.
  Пути доктрины — как в файле (`main.escort_weight`, `sec.mounts.cruiser`,
  `clan.troyden.gunMod`), выгрузки — с `space.` и id вместо номера
  (`space.ships.plektor.cruiser.hp`). Правка ссылки (`ref`) — отказ
  с подсказкой, что править. Что применено — `defs.overrides_applied`.
- Сверка загрузчика с выгрузкой поле за полем — `test_sim_defs.gd`:
  1540 полей, допуск 1e-9; пропуски названы с причиной (`SHIP_SKIP` и др.).
  Новое поле в выгрузке без загрузки или пропуска — провал теста.

## 13. Сборка и доставка
- Workflow — `.github/workflows/capella-godot.yml` в КОРНЕ репозитория;
  срабатывает только на пуш в `claude/capella-godot*` с правкой
  `godot/**` или самого файла (и на метку `capella-v*`).
  Задания: `test-build` (ubuntu: кэш Godot и шаблонов со сверкой SHA512 →
  `run_tests.sh` → выгрузка → ЗАПУСК Linux-сборки `-- --selftest` →
  zip → артефакты на 7 дней), `windows-run` (windows-latest:
  `capella.console.exe --headless -- --selftest`, отпечаток данных
  сверяется с Linux), `release` (черновик выпуска).
- **Выпуски — ТОЛЬКО ЧЕРНОВИКОМ** (`gh release create … --draft`):
  репозиторий публичный, опубликованный выпуск видят все, согласия
  пользователя на это пока нет. Черновик видит только владелец.
- **Выпуск — по новому номеру в `godot/RELEASE`** (дверь 3): первая
  строка — номер `capella-vX.Y`, вторая — заголовок, третья `---`, дальше
  текст выпуска по-русски («что нового, как запустить, что нажать»).
  «Новый» — выпуска (и черновика) с таким номером ещё нет; есть — задание
  молчит. Номер поменял — после зелёных тестов и запуска обеих сборок
  появится черновик с `capella-windows.zip` и `capella-linux.zip`.
- Ловушки CI: имя `godot` в корне занято папкой — программа в
  `~/godot-bin`; папку сборки создавать заранее, в ней `.gdignore`;
  у черновика нет метки — никакого `--cleanup-tag`; метки — в
  `on.push.tags`; консольная обёртка Windows для выпускной сборки —
  `debug/export_console_wrapper=2` (по умолчанию 1 — только отладочная);
  `application/modify_resources=true` на Linux прошёл без rcedit.
- Сборки в git не кладём (`build/` в `.gitignore`); `*.gd.uid` и
  `*.gdshader.uid`, `*.import` — кладём. Удалил скрипт — удали и его
  `.uid` (сирота остаётся молча).
- **Двери выпуска — проверено в G0a (10.10.2026):**
  1. пуш метки `capella-v*` из сеанса — **НЕ работает**: прокси отвечает
     HTTP 403 (как и на удаление ветки). Метку создаёт только сам workflow
     или пользователь руками;
  2. **`workflow_dispatch` РАБОТАЕТ** и без файла в `master`: вызов
     `actions_run_trigger` (MCP github, `run_workflow`, `ref:
     claude/capella-godot`, `workflow_id: capella-godot.yml`) поставил
     прогон `38064945933` на ветку. Слова документации GitHub «только
     если файл лежит в ветке по умолчанию» здесь не подтвердились (файл
     уже был зарегистрирован пушем в ветку). Значит, можно и кнопкой:
     поле `release` — черновик под этим номером, пусто — только тесты;
  3. **новый номер в `godot/RELEASE` — работает** (основная дверь):
     прогон `38064824358` по пушу создал черновик `capella-v0.0.1`
     с `capella-windows.zip` (38,0 МБ) и `capella-linux.zip` (28,4 МБ).
     Следующий пуш с тем же номером черновик не плодит — проверка «такой
     выпуск уже есть» стоит в задании `release`. **Черновики видны только
     с правом записи**: у задания с `contents: read` `gh release list`
     черновик не показывает, и первая версия (проверка в `test-build`)
     собралась было завести второй черновик с тем же номером — прогон
     `38064945933` пришлось остановить.
- Ветки и метки отсюда не удаляются и не создаются (прокси отвечает 403) —
  просить пользователя. Черновик выпуска удаляется через MCP/gh, если нужно.
- Предупреждение Actions «Node.js 20 is deprecated» у `actions/*@v4` —
